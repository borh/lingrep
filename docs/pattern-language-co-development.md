# Pattern language co-development guide

How to change the `.lx` pattern syntax, which spans two repositories:
[tree-sitter-lingrep](https://github.com/borh/tree-sitter-lingrep) (the grammar)
and lingrep (the compiler and matcher).

## The two repositories

### tree-sitter-lingrep

- `grammar.js` defines the syntax rules; edit this file.
- `src/parser.c` is generated by `tree-sitter generate`.
- `bindings/rust/lib.rs` is the Rust binding Cargo builds.
- `queries/` holds the editor queries.

### lingrep

- `lingrep-core/src/fsm/compiler/lower.rs` lowers the CST strictly to a typed
  program.
- `lingrep-core/src/fsm/compiler/bind.rs` binds names across the document and
  validates them.
- `lingrep-core/src/fsm/compiler/nfa.rs` lowers validated expressions to the NFA.

lingrep takes tree-sitter-lingrep as a Cargo git dependency pinned to one
revision in the root `Cargo.toml`:

```toml
[workspace.dependencies]
tree-sitter-lingrep = { git = "https://github.com/borh/tree-sitter-lingrep.git", rev = "<grammar-commit>" }
```

`Cargo.lock` records the same revision. Cargo fetches the dependency into its own
cache; a `third-party/tree-sitter-lingrep/` clone, which `.gitignore` excludes,
is a convenience for editing and is not used by the build.

## Change the syntax

### Step 1: Edit the grammar

```bash
git clone https://github.com/borh/tree-sitter-lingrep.git
cd tree-sitter-lingrep

# Edit grammar.js, then regenerate src/parser.c
tree-sitter generate
tree-sitter parse /path/to/lingrep/patterns/sfe.lx  # validate against a real catalog

git add grammar.js src/parser.c
git commit -m "feat: <new construct>"
git push
```

### Step 2: Update lingrep to the new grammar

```bash
cd /path/to/lingrep

# Set `rev` in the root Cargo.toml to the grammar commit you pushed, then:
cargo update -p tree-sitter-lingrep

# Edit lingrep-core/src/fsm/compiler/lower.rs
# Edit bind.rs or nfa.rs only if the language meaning requires it
# Update lingrep/src/pattern_reference.rs (`ling check --help` and ling-check(1))
# Add compiler-contract tests in lingrep-core/tests/suite/pattern_compiler_contract.rs
# Update docs/pattern-language-reference.md for a user-visible change

cargo test -p lingrep-core --test suite -- pattern_compiler_contract::pinned_tree_sitter_parses_repository_catalogs --exact

git add Cargo.toml Cargo.lock lingrep-core/src/fsm/compiler lingrep/src/pattern_reference.rs \
  lingrep-core/tests/suite/pattern_compiler_contract.rs docs/pattern-language-reference.md
git commit -m "feat: <new construct>"
```

### Step 3: Validate against real catalogs

```bash
dict_root="$(nix build .#vibrato-dictionaries --no-link --print-out-paths)"
ling check --patterns patterns/sfe.lx
ling matches --patterns patterns/sfe.lx \
  --dict-path "$dict_root/share/vibrato/unidic-cwj-202512.dic" \
  data-archive/test-corpus.jsonl
```

## Required CST protocol checks

A named CST-node change is a versioned protocol change, even when matching
semantics are preserved. Before committing the new Cargo pin, verify all of:

1. tree-sitter corpus trees and repository catalogs contain no `ERROR` or
   `MISSING` nodes;
2. editor queries compile against the new grammar, and the browser editor's
   WASM and highlight manifest are regenerated from the exact pinned grammar
   commit;
3. the strict lowerer consumes the new node names without an old-CST
   compatibility branch;
4. the exact pinned-grammar integration test exercises the changed CST shape;
5. typed catalog/compiler fingerprints remain equal;
6. complete canonical `Match` values agree with the independent typed-expression
   oracle; and
7. `lingrep/src/pattern_reference.rs` documents the changed syntax in
   `ling check --help` and `ling-check(1)`.

The grammar pin, lockfile, strict-lowerer support, and CLI syntax reference
belong in one atomic lingrep commit. A grammar commit may be published first,
but its Cargo pin must not land without the matching lowerer and reference.

## Semantics a grammar change must keep

[pattern-language-reference.md](pattern-language-reference.md) specifies the
language, and `ling check --help` is the installed syntax reference. A grammar
change keeps that behavior unless the same change updates the reference, the
runtime tests, and the CLI reference together. In particular:

- A CST that contains an `ERROR` or `MISSING` node is rejected even when
  tree-sitter returns a tree.
- The runtime compiler validates regex values; grammar acceptance alone is
  insufficient, and an invalid regex is `InvalidRegex` with a source location.
- `key:` has a dedicated CST and lowers directly to an ordered typed list, not
  to general map metadata.
- Successful compilation is atomic and budgeted. Applications consume stable
  diagnostic codes and spans, never message text.
