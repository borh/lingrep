# lingrep 0.8.0

Set up GiNZA 5.3.1 from this release's adapter wheels:

```bash
ling analyzer prepare ginza --output ./analyzers/ginza-0.8.0
```

The spaCy adapter installs GiNZA 5.3.1 with `ja_ginza` 5.3.0 and spaCy 3.8.18.
Its `electra` extra installs `ja_ginza_electra` 5.3.1, and a new `bert-large`
extra installs `ja_ginza_bert_large` 5.3.0. A GiNZA selection publishes
bunsetu (文節) segmentation as `spacy.ginza.bunsetu`, `B` on each
bunsetu-initial token and `I` on the others, equal to `ginza -f conllu`'s
`BunsetuBILabel`:

```text
pattern bunsetu_head := [spacy.ginza.bunsetu=B].
```

GiNZA's profiles now run the whole pipeline, so dependencies and UPOS equal
`ginza -f conllu`; the 0.7.0 profiles were tokenizer-only or ran the parser
without its `tok2vec`. Setup saves the transformer weights of
`ja_ginza_electra` and `ja_ginza_bert_large` in the analyzer, downloaded once
at a pinned Hugging Face Hub commit, and analysis runs with Hub access
disabled.

`ling serve` and `lingrep-web` open on a question page: a search with complete
concordances, metadata conditions, a token lab that draws the dependency arcs
between the words a match binds, with a 文節 view, document reading and JSONL
export. The Workbench is at `/workbench`. Frequencies lines open the matching
occurrence in the token lab.

Export the words a match rests on, including a verb that a `where` clause
binds outside the span:

```bash
ling matches --corpus works.lingcorpus --patterns patterns/npv-collocation.lx \
  --json --evidence
```

`examples/compare_occurrences.py` compares two such streams by role words and
writes one row per occurrence found by one pattern, the other, or both.

Other additions: `matches --publish-attribute KEY` and
`--publish-all-attributes`; `table --by-document --json` for sparse
per-document counts; `summarize --grouping-coverage`; `--pattern-filter` and
`--group-patterns-by` for `summarize --by-section`; overlap modes `catalog`,
`keep` and `longest`; `--serve` and `--link` on `matches` and `summarize`;
`--vectors FILE` for `near` tests and a Similar Words page; `table --key
FIELD=VALUE` subsets; and `--download-base`/`LING_DOWNLOAD_BASE` mirrors for
adapter wheels and dictionaries.

## Upgrading

- Prepared artifacts use generation 3 and provenance schema 5. Rebuild
  generation 2 artifacts with `ling corpus build`.
- Set up existing spaCy and Stanza analyzers again into a new directory. The
  changed GiNZA and `en_core_web_sm` profiles and the 0.8.0 adapter wheels
  change analyzer identity, and corpora prepared with those analyzers have new
  identities; rebuild them. Transformer analyzers set up by earlier releases
  fetched their weights from the Hub at whatever commit it served each time
  they started.
- Rebuild Markdown artifacts and reading sidecars: the reader and renderer
  identities advance with the display-math, table-boundary and alignment
  fixes.
- Word graph bindings publish `norm` when the token carries it, which changes
  default output for corpora with both `norm` and dependencies.
- `ling serve` and `lingrep-web` exit with status 1, not 2, when a corpus,
  listener or runtime fails to start.
- Rust API users: error variants change shape and `AnalysisError` no longer
  implements `Clone` or equality.
- Graph matching fails with a named resource error, such as
  `match_batch_too_large`, when a sentence or matching batch exceeds its
  budgets, instead of exhausting memory.
