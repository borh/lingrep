# lingrep 0.5.1

Prepare a GiNZA or Stanza CPU analyzer without a source checkout:

```bash
ling analyzer prepare ginza --output ./analyzers/ginza
ling matches --analyzer-config ./analyzers/ginza/analyzer.toml \
  --patterns constructions.lx transcripts/
```

Preparation requires `uv` on PATH. The output directory contains Python 3.14,
installed dependencies, the model and verified analyzer configuration. Clearing
Python download and package caches does not break the analyzer. Keep the output
at its original path; queries use the configuration without installing or
updating anything. Repeating the same preparation checks and reuses the directory.
Stanza preparation accepts an explicit language and processor/package selection.
Delete an analyzer's output directory to remove its runtime and model. Locate
shared downloads with `uv cache dir` and clear them with `uv cache clean`.
See the [CLI guide](https://github.com/borh/lingrep/blob/v0.5.1/docs/cli-usage-guide.md#use-an-external-protocol-adapter)
for both setup paths.

Releases include the protocol, spaCy and Stanza wheels in `SHA256SUMS`.
Wheel contents, license metadata and installed setup commands are checked before
tagging. Runtime dependencies use hash-pinned lock exports; the PyTorch index
is restricted to PyTorch packages. CPU setup selects native Torch builds on
macOS and Linux. Nix analyzer packages include readable license files for the
adapter and shared protocol.

Adapter package versions follow the CLI release. Preparing with later wheels
changes analyzer and prepared-corpus identities even when adapter code is
unchanged. Output directory names do not affect managed analyzer identity.
Upgrading `ling` alone leaves existing bundles unchanged; existing
prepared corpora remain usable while their format is supported.
