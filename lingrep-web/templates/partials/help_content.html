lingrep patterns syntax help

lingrep patterns documents contain complete pattern declarations. A bare definition or pattern emits matches; a fragment is reusable but does not emit results; a set is a named value, not a definition, and neither emits nor is directly matched.

Token predicates

Use =, !=, in, not in, and /regular expressions/. Combine constraints inside a token with &.

Composition

Whitespace sequences expressions, | alternates, parentheses group, and @NAME references a fragment, a pattern, or a set. Quantifiers are ?, *, +, and {n,m}.

Captures and comparison

(?<name> ...) creates a named capture. same_as($name, by=unidic.kana) consumes a span equal by text, lemma, unidic.kana, or unidic.pron.

Boundaries and assertions

^ and $ assert sentence boundaries. preceded_by(E) and followed_by(E) require a regular expression to end or start at the current boundary without consuming it; not_preceded_by(E) and not_followed_by(E) complement those tests. Assertion bodies may be variable-width or nullable, but may not contain captures or same_as.

Dependency graphs

A where clause constrains basic dependency edges between captures. Enhanced edges use -[enhanced labels]->, may introduce a word or decimal empty node with (?<name> [test]), and may name the exact edge with as $edge. Every graph component requires a surface capture anchor; each complete assignment is one match.

Pattern editor

The pattern editor highlights lingrep patterns syntax and checks it as you type. Hover any attribute, value, @reference, or $capture for its documentation; typing same_as( shows the call signature inline with the active argument underlined.
